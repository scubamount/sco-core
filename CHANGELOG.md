# Changelog

sco-core has no releases yet. sc-offline pins a commit; this file lists what each change means for sc-offline.

## Unreleased

- **Docs: design proposal for game-file overrides and DataCore patches** ([docs/design/vfs-datacore.md](docs/design/vfs-datacore.md)), a Phase 6 item: how sc-offline's byte-diff DCB patch works and why every game patch turns it off, the DataCore layout measured on 4.10.193 (records are 36 bytes), `sco::vfs`, a semantic patcher, `.toml` overrides in data packs, tests and a PR plan. Docs only.
- **`sco/hook.h` v2**: `StolenLength` (instruction-length decoding for the usual prologue set; refuses RIP-relative and relative-branch code) and `InstallDetour(target, 0, ...)` to count stolen bytes automatically; a far path (`FF 25` absolute jump over 14+ stolen bytes) when no cave fits within ±2 GiB; `MemoryProtectScope` (RAII protection, now under `WriteCode`); `RemoveAll`; opt-in `Transaction` for hooks that only make sense together (sc-offline's independent hooks keep using `InstallDetour`). Existing calls behave as before, except `stolen = 0`, which was `BadArg` and now means "count it". [api.md](docs/api.md#scohookh-detours-and-near-code-memory).
- **`sco/engine/types.h` and `sco/engine/zone.h`** (library `sco_engine`; `sco_api.h` unchanged): header-only 64-bit `Vector3d` / `Quatd` / `Transform`, with `FromXYZW` / `ToXYZW` for the game's (x, y, z, w) `double rot[4]`, and `ZoneTree`, nested zones the host feeds each tick (`Set` / `Remove`) with `LocalToWorld`, `WorldToLocal` and `Transform` between zones (via the common ancestor; false for a missing zone, a cycle or more than 32 levels). Pure math: no game offsets, no game memory; sc-offline keeps reading the game's zones and feeds them in. Groundwork for the spatial service ([framework plan](docs/framework.md)). `tests/test_spatial.cpp` runs under ASan+UBSan and ThreadSanitizer.
- **C++20 SDK layer** (`include/scosdk/`, [docs](docs/sdk-cpp.md)): header-only, over `sco_api.h` 1.1 (unchanged), standard library only. `sco::sdk::Plugin` with `OnLoad`/`OnUnload`, printf-style logging, `RunOnGameThread` and `Subscribe` handles; `SCO_PLUGIN` writes the three exports; `CommandBuilder` with typed `Args`/`Reply`; `Provide`/`ServiceRef<T>`/`HasMember`; `RegisterRaw<In, Out>`/`InvokeRaw` with the size handshake, plus byte-span forms. Every callback's ctx is an id into a registry swept at unload, so nothing the SDK frees can be called late; no exception crosses the C ABI (`SCO_FAILED` and a log line instead). New test `test_sdk` (two SDK plugins through the real host table; ASan+UBSan and TSan in `tools/test.sh`, CTest on Linux and MSVC). The SDK zip ships `include/scosdk/`, `docs/sdk-cpp.md` and the `cpp_hello` example, which `sdk/test-zip.sh` builds and checks with MSVC and gcc. sc-offline needs no change.
- **sco_api 1.1** (`SCO_API_MINOR` 1; 1.0 plugins load unchanged): `SCO_FAILED` (7), the result for a command or service that ran but couldn't do its job (#12). Services: `provide_service(self, name, version, vtable)`, `query_service(name, min_version, out_vtable)`, `release_service(self, name)`, function tables one plugin publishes for others under `<id>.<name>` with `(major << 16) | minor` versions, withdrawn when the provider unloads or crashes ([API v1 § Services](docs/api-v1.md#services-11)). Raw handlers: `register_raw` / `invoke_raw`, byte-in byte-out calls on the game thread with a capability check, the crash guard and a size handshake ([API v1 § Raw handlers](docs/api-v1.md#raw-handlers-11)). `sco_api` grows from 88 to 128 bytes; `tests/abi_v1.c` pins it. The 1.1 service signatures changed before any tag: the `sco_service_def` struct of #14 is gone. Plugins built with this header report api 1.1 in `sco_plugin_info` and need a 1.1 host.
- **Discovery refuses a plugin folder whose id belongs to a built-in** (`the id belongs to a built-in plugin`), for every kind, data packs included (#11). `sco::plugins::Options` gains `builtins` / `nBuiltins`; `sco::app::Start` fills them from `Platform`.
- **`sco/hook.h`** (library `sco_hook`): near-code caves, `WriteCode`, `InstallDetour` / `RemoveDetour` with one detour per target, so a product's hooks and plugins share one patcher. sc-offline's `hooks.cpp` moves onto it next. `tests/test_hook.cpp` detours real code in executable memory on Linux and Windows.
- **Docs: Phases 1-3 done, lessons learned** ([framework plan](docs/framework.md#lessons)): sc-offline builds with CMake (sc-offline PR #55, `88e7830`) and runs on sco-core's host kit (sc-offline PR #56, `78756af`, played in game 2026-10-09; plugins off by default). Five lessons with their rules: call `sco::app::Stop` from the game's quit path, since the game's Quit never sends `WM_QUIT` (`game.exit` is best effort); start the host kit regardless of any one feature; aliases can't share a name with a function; the CMake settings a consumer needs ([building](docs/building.md#using-sco-core-from-another-cmake-project)); plugin loading never shows the Bad Image box (`933701a`, `SetThreadErrorMode`). CONTRIBUTING: lessons flow back to sco-core in the same cycle. README, the SDK status and the docs index describe sc-offline on sco-core. Docs and comments only.
- **`system.quit`** (`sco/game/system.h`, `src/game/system_sigs.cpp`): CSystem::Quit, found from its `CSystem::Quit invoked with - cause=$$, ...` log line, and `sco::game::QuitFunction` (entry plus the 15 whole prologue bytes a detour may overwrite). With ExitOnQuit the game ends inside that function without WM_QUIT, so sc-offline can hook it to run `sco::app::Stop` first. The startup report becomes `N/5`; build 4.10.193.11644 (CL 12660092): `5/5 OK`, `system.quit` at RVA `0x7237c60`. `tools/test.sh` now builds `test_core` with `src/game/*.cpp`.
- **Host kit** (`sco/app.h`, `src/app/`, [API](docs/api.md#scoapph-the-host-kit)), framework plan Phase 2: `sco::app::Start`/`Tick`/`Stop` run the startup order every product needs (signatures, capabilities, the `sco_api` table, built-in then discovered plugins, the content index, the reports, `game.ready`; `game.exit` then unload), never fatal. **Built-in plugins** (`Kind::Builtin`, `FromBuiltin`, `LoadBuiltin`): features compiled into the product, with the loader's checks and crash guard, listed as `builtin` and unloaded after every other plugin. **`sco-host-sim`** runs the real host kit, loader and sco-lua outside the game. New tests `test_app` and `host_sim_examples` (the SDK examples through `sco-host-sim`) on Linux and Windows. sc-offline doesn't call it yet.

- **Framework plan** ([docs/framework.md](docs/framework.md)): proposal for sco-core as the heart of a framework for mods of any kind: a host kit products start from, built-in plugins, local storage (key-value and SQLite) and services between plugins, and sc-offline rebuilt on it (CMake first, then its features as built-in plugins). Nothing built yet.
- **Crash containment for plugin callbacks** (`sco::SetCalloutGuard`, `sco::plugins::ContainCallouts`): every task, event callback, command and `invoke` `done` callback a plugin owns now runs through the loader's crash guard, so a native plugin that faults in `tick` or a command is disabled instead of ending the game, and a faulting command answers `SCO_CRASHED`. Before, only `query`, `load` and `unload` were guarded. `done` is no longer called for an owner released during its own command. The loader never unmaps a plugin whose `Release` failed, keeps a nested crash's state, loads DLLs by absolute path (`LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR` needs one), rebuilds the content index without dropping loaded packs, and refuses a pack it can't read completely.
- **sco-lua limits**: error objects are never converted outside protected mode (a number error at the memory cap could `abort()` the game); at most 64 functions per event and 16 queued tasks per script; `table.unpack`/`pack`, `string.byte`/`char`, long plain `find` needles and long bracket classes are charged in proportion to their work. `sco-plugin-check` applies the host's exact `plugin.ini` and command rules.
- **CMake build** (`CMakeLists.txt`, [Building and testing](docs/building.md)): the libraries, `sco-sigcheck` and every unit test under CTest, for any CMake toolchain. New CI workflow `cmake` builds and runs it on Linux (clang, ASan+UBSan) and on Windows with MSVC x64, so the real target compiles in CI; `tools/test.sh` stays the reference with the TSan runs.
- **Docs**: README rewritten around the game core and the plugin platform, [docs index](docs/README.md), [Building and testing](docs/building.md); CONTRIBUTING covers the ABI rule, the test files and both builds.
- **sco-lua** (`plugins/lua/`, [readme](plugins/lua/README.md)): runs `kind = lua` plugins. Lua 5.4.8 (vendored, MIT, sha256 checked against lua.org) in a sandbox: `string`/`table`/`math`/`utf8` and safe base functions only, text chunks only, no `__gc`. 1 million steps per entry (VM instructions plus patched string and table library loops), 64 MiB per script, disabled after an overrun or 3 errors. Built only on `sco_api.h`. The loader gains `LoadScript` and `ScriptRuntime`; `UnloadAll` also unloads scripts. `tools/test.sh` runs `tests/test_lua.cpp` (incl. the SDK's `greeter` example) under ASan+UBSan.
- **Discord feed**: `.github/workflows/discord.yml` posts releases, merged PRs, issues opened or closed, and pushes to `main` to the sc-offline Discord channel, the same way sc-offline does. It needs the `DISCORD_WEBHOOK_URL` Actions secret; without it the job warns and posts nothing.
- **Capabilities and the host table** (`sco/caps.h`, `sco/host.h`, `src/api/sco_caps.cpp`, `src/host/`): `caps::Set`/`Has`/`List` and `SetFromSignatures` (ready when its signature rows are OK). `host::BuildApi()` fills the one `sco_api` table over the runtime, caps, status and log and wires the command capability check to `caps::Has`; `host::NewPlugin(id)` gives per-plugin handles that are also runtime owners. `list_commands` returns host-built `sco_command` views. sc-offline doesn't call either yet. `tools/test.sh` runs `tests/test_host.cpp` under ASan+UBSan and ThreadSanitizer.
- **Plugins** (`sco/plugins.h`, `src/plugins/`, [docs](docs/plugins.md)): `data/plugins/<id>/plugin.ini` discovery and parsing (off/disabled/refused/ready with a reason), the native loader (`LoadLibraryExW` from the plugin folder and System32 only, query/version/name checks, `__try` guard on every call into plugin code; a fault releases the plugin and keeps its DLL mapped), and the data-pack content index (missions, rules, scripts, lists). sc-offline doesn't call it yet. `tools/test.sh` runs `tests/test_plugins.cpp` against real fake plugins; `tools/test-win.sh` runs the same tests as a Windows build under Wine.
- **Plugin SDK** (`sdk/`, 1.0-pre): a template and three examples (`hello` native C plugin, `travel_pack` data pack, `greeter` Lua script), `cmake/sco-plugin.cmake` (`sco_add_plugin`, `sco_add_pack`), `tools/sco-plugin-check.c` (loads a built plugin against a stand-in host that enforces the documented rules) and `tools/lua-check.lua`, and docs for plugin.ini, data packs, Lua and plugin rules. `sdk/package.py` builds a reproducible `sco-sdk-<version>.zip` with `SHA256SUMS`; `sdk/test-zip.sh` builds and checks every example from the unpacked zip alone. New CI workflow `sdk` runs it on Linux and on Windows with MSVC and keeps the zip as an artifact. `tools/test.sh` also compiles the template, `hello` and `sco-plugin-check` against `sco_api.h`. Nothing in sc-offline loads plugins yet.
- **Runtime** (`sco/runtime.h`, `src/api/`): game-thread task queue (256, in order, `TooMany` when full), event bus (subscribe/unsubscribe from any thread, changes apply from the next dispatch) and command registry (`RegisterCommand`, `ListCommands`, `Invoke` with argument, capability and owner-prefix checks). `GameThreadTick()` drains the queue then dispatches `tick`. sc-offline doesn't call it yet; wiring `OnMainThreadTick` to it is the next sc-offline change.
- `tools/test.sh` also builds and runs `tests/test_runtime.cpp` under ASan+UBSan and ThreadSanitizer.
- **Runtime and ABI review fixes**: a task that ticks or drains no longer corrupts the queue (nested drains are refused); `Release(owner)` removes an owner's subscriptions, commands, queued tasks and queued invokes, for plugin unload; `Unsubscribe` applies at once and the docs give the safe point for freeing `ctx`; `RegisterCommand` copies every string and arg def, takes an owner, and refuses reserved or foreign prefixes; `Bool` args must be 0 or 1; nothing throws. `sco_api.h`: 4-byte enums (`_FORCE32`), `sco_command.arg_def_size` so `sco_arg_def` can grow, `done` and `list_commands` rules spelled out. `tools/test.sh` pins the ABI for `x86_64-pc-windows-msvc` and with `-fshort-enums`, and runs real cross-thread overlap tests under ThreadSanitizer.
- **Plugin ABI 1.0-pre**: `include/sco_api.h`, the plain-C header plugins will include ([reference](docs/api-v1.md)). Declarations only; nothing implements or loads it yet. `tests/abi_v1.c` pins every v1 size, offset, enum value and signature; `tools/test.sh` compiles it as C11 and C++20 (CI now passes `CC=clang`).
- **Docs**: README, [How it works](docs/architecture.md), [Adding a signature](docs/adding-signatures.md), [Checking a game build](docs/sigcheck.md), [API reference](docs/api.md), CONTRIBUTING.md and this changelog.

- Teleport's four addresses as `teleport.*` rows, moved byte for byte from sc-offline's `src/teleport.cpp`.
- `tools/sco-sigcheck`: runs every table against a `StarCitizen.exe` on disk.
- `tools/test.sh`: 42 unit checks with AddressSanitizer and UBSan.
