# Changelog

What each change means for plugin authors and for products built on sco-core (sc-offline). SDK releases are tagged `sdk-v<version>` and published with `sco-sdk-<version>.zip`; between releases, sc-offline pins a commit.

## Unreleased

- **`sco.ipc` 1.0 and the MIT wire `sc_ipc.h`** (design [section 3.3](docs/design/multiplayer.md#33-sc_ipch-the-wire-mit-and-the-scoipc-service-the-in-game-wrapper); `sco_api.h` unchanged; [docs](docs/ipc.md)). **`include/sc_ipc.h`**: header-only C11 / C++20 with freestanding headers only, `SPDX-License-Identifier: MIT` (the interface exception, now in `LICENSE` and `CONTRIBUTING.md`), so the non-GPL side of a bridge includes it alone. It defines the 64-byte channel header (magic, version, pids, epoch, both heartbeats, size, layout id/version, state), single-producer single-consumer byte rings (64-bit counters on their own cache lines, power-of-two capacity, the pad record when a record doesn't fit before the end) and seqlock blocks, every layout `static_assert`ed, an atomics shim over compiler builtins (MSVC x64: volatile and compiler barriers), and hostile-peer checks: geometry is validated once against the OS's view size and cached locally, and every counter, length and record header read afterwards is checked before use (`SC_IPC_CORRUPT`, never an access outside the mapping). **`include/sco_ipc.h`**, a host-owned service pinned by `tests/abi_ipc.c`: `create` (`Local\SCO_<plugin id>.<name>`, built by the host; DACL and owner for the current user only; 256 MiB per channel, 512 MiB and 16 channels per plugin), `peer_age_ms`, `block_write` / `block_read`, `ring_init` / `ring_push` / `ring_pop` (one direction per ring, the size handshake), `view`, `close`; ids, never pointers (`view` excepted: the plugin's own mapping). Closed (`SC_IPC_GONE` for the peer), heartbeat stopped and unmapped when the plugin unloads or crashes. Host side `sco/ipc.h`, library `sco_ipc` (`src/ipc/ipc.cpp`, `shm_win.cpp`, and `shm_posix.cpp` for the tests); the host kit starts it, writes the owner heartbeat from `Tick` and stops it after `UnloadAll`. **`scosdk/ipc.hpp`** (`Ipc`, `IpcChannel`). The SDK zip ships both headers and `docs/ipc.md`. Tests: `tests/test_ipc.cpp` under ASan+UBSan and TSan (ring wrap and padding, full/empty, the size handshake, sequence rollover across 2^64, epoch changes, torn headers and blocks, bad magic/version/layout, oversized and impossible lengths, counters and offsets, a seeded fuzz of scribbles, writer/reader threads; the service over real shared memory with the peer as a second mapping opened by name: names, quotas, directions, overlap, a hostile peer, heartbeats, close and unload). Deferred to a follow-up: the C# wrapper and a two-process test. Lua gets no `sco.ipc` (by design). For sc-offline: link `sco_ipc` (the host kit does); nothing else until a bridge uses it.
- **Design: co-presence multiplayer and cross-game bridges** ([`docs/design/multiplayer.md`](docs/design/multiplayer.md)), for review, no code: the scope change of 2026-10-09 (sessions between players running sc-offline, local links to other games), updated to the maintainer's directive — co-presence by ghost replication (no dedicated server, the excluded patches named and never ported), the `sco.net` channel service and the `sco.ipc` / MIT `sc_ipc.h` bridge wire, a vendored SHA-256/HMAC/PBKDF2, `spawn.entities` 1.2, and the 7-PR plan.
## sdk-v1.1.0 (2026-10-09)

The first SDK release. The plugin ABI is version 1.1 and stable from here on: version 1 only grows at the end of structs, so plugins built with this SDK keep loading in later 1.x hosts.

- **One ABI, five ways to write a plugin:** C against `sco_api.h`, C++20 with `scosdk/`, C# with `Sco.Sdk` (published with NativeAOT, no .NET needed by players), sandboxed Lua 5.4, and data packs with no code.
- **Host services**, each with its own pinned header: `sco.storage` (per-plugin key-value and SQL over SQLite, crash-safe), `sco.ui` (menu tabs, overlays, badges, hotkeys bound to commands), `sco.datacore` 1.1 (DataCore overrides, new instances and new records, applied at the game's data load or saved for the next launch). Plugins provide services and raw handlers to each other.
- **Data mods that survive game patches:** `.toml` packs address DataCore records and fields by name; `sco-dcb` lints them and checks them against a game build.
- **Host side for products:** the host kit, built-in plugins, crash containment, the detour engine, 64-bit engine math and the zone tree, virtual game files (`sco::vfs`, `sco::game::pak`), and the signature tables with `sco-sigcheck`.
- **SDK zip** `sco-sdk-1.1.0.zip`: headers, template, seven examples (`hello`, `cpp_hello`, `cs_hello`, `greeter`, `notebook`, `travel_pack`, `quantum_pack`), the CMake helper and `sco-plugin-check`, each example built and checked from the zip on Linux and Windows in CI.

The pack format gains `[[record]]` (`struct`, `name`, `clone` = a record of the same struct; optional `id` shared with `[[instance]]` ids, `guid`, `file`, `set`), run through `Patch::AddRecord` with R1's rules; later operations name the new record by name, GUID or `"@id"` (its root).
